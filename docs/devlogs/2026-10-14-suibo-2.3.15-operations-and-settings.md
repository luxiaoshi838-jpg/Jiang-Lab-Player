1. **每轮改代码/规则/界面/配置**：同一轮提交之前或完成时，在 `docs/devlogs/` 当日日志追加一条，列出执行动作、修改的确切文件、关键参数与生效范围、为什么修改、结果、提交 SHA/PR 链接。
2. **每轮 GitHub Actions / 构建/交付**：记录具体运行 ID、成功/失败/取消/跳过，不把“已触发”写成“已通过”；完成后核验产物名称、大小、校验结果。不能把 CI 模拟成实体设备验收。
3. **每轮 Render / 外部配置变更**：记录服务 ID、脱敏设置名称、变更前后非敏感值、deploy ID、最终状态与公开验证结果；禁止保存 token、secret、签名凭证。
4. **每轮密钥/签名操作**：只记“从哪里读取、是否使用原有证书、校验是否通过及报告位置”，不写密钥值、不提交私有文件。
5. **失败与未完成也写**：标明失败原因和未解决事项，严禁把失败/待验证修改成成功；需要后续纠错时追加更正，保留原事件。
6. **便于访问**：仓库 `README.md` 和 `docs/devlogs/README.md` 保持最新日志链接；每轮完成后通过 GitHub 文件读取确认日志真实存在。源码提交记录与 GitHub Actions 原始日志是更细粒度证据。
