# 随播 2.3.19：智能播放与来源优化（开发日志）

基线：`fix/suibo-2.3.15-danmaku-episode-resolution` 的 HEAD `5e8aefb`，该分支 `pubspec.yaml` 已是 `2.3.18+20318`。开发分支：`feature/suibo-2.3.19-smart-playback`。

## 范围与限制

- 仅修改现有 Flutter/Dart 来源检索、播放恢复和预解析。**未改变** Kazumi 规则安装/解析格式、原弹幕查询/画布绘制、media_kit/mpv 播放器、首页布局或影视类型。
- 全部新增/更新源码通过 GitHub 版本历史追溯。无需下载或上传安卓签名文件；Google Drive 原签名密钥未接触、未重建。
- 本次只开启下一集真实地址/明文 HLS 播放列表预解析。未验证播放器与独立分片缓存共享通道，因此分片下载**明确禁用**，不能宣称分片加速。
- 不能在当前编辑环境运行 Flutter、Windows Release 或 Android APK 正式签名。CI 和设备回归结果必须单独审查。

## 源健康度（SourceHealthService）

- 本地 Hive settings 按来源规则名称记录搜索命中、列表解析、视频参数首次出现耗时、播放缓冲次数/累计时长与错误次数；不持久化流地址、token、请求链接。
- 采用平滑得分；新来源保留中性得分，不因历史样本不足扣分。仅观测足够时显示“稳定”“较慢”；严重近期失败进入10分钟冷却，仍保留规则。
- 已在“播放来源”旧弹层中排序及显示状态；手动成功选择的来源对该作品享有最高优先级（本地记录）。
- 当前首次视频参数事件只是首次解码参数可用的观测代理，非屏幕像素真正出画测量。真实首帧性能对比仍须真机埋点和实测。

## 故障恢复

- 对连接超时/断线先延迟2秒及5秒，最多两次；持续失败仅试一次严格同集换源。解码错误及未知错误不自动盲目换源。
- 先比对集标题实际提取的明确集号；不以列表索引充当同一集。跨规则还要求作品标题精确匹配已知名称/别名及候选来自原作品聚合结果。
- 切源保留秒级进度、播放速度、弹幕开关并触发当前既有弹幕重取，不更改弹幕提供商；未找到可靠匹配只提示手动换源。
- 手动跳集、离开、重启期间取消旧的观察、查询/预加载任务，拒绝过期结果。
- 监测长时间缓冲，等待20秒且确认当前播放器仍是同一个时才按网络故障处理，避免瞬时缓冲触发切换。
- 缓冲/失败监听来自当前 media_kit Player stream；播放器原有缓存策略保留不变。

## HLS 安全预解析

- 接近片尾90秒、当前视频时长至少3分钟、可明确确认下一集集号递增1且功能开启时触发。
- Android 只在前台、且即时检查为 Wi-Fi/有线时执行；移动网络及类型不明默认跳过。
- 流解析采用独立可取消的 WebView 服务；仅对普通 http(s) HLS m3u8 有限读取播放列表（上限256KiB，8秒网络超时）；含加密 KEY、SESSION-KEY、DRM 字样的列表不预备。
- 仅短期保存已校验的下一集媒体 URL（90秒）供切集复用。播放器继续直接处理 HLS 下载及分片缓冲；无第二套分片下载器，也无声称已验证的缓存命中。
- Windows 现有网络类型服务未能可靠确定计量状态；本版尚需平台网络成本验证，不能宣称 Windows 计量网络限制已完成。

## 视频临时缓存

- mpv `demuxer-cache-dir` 使用独立的 `suibo-mpv-cache` 文件夹，而非全应用临时目录；不会影响图片缓存及用户保存的下载文件。
- 每次新建播放器前，只在无存活播放器时按 7 天过期阈值清除旧文件；“存储与日志 → 清除视频缓存”仅清理专用目录，播放器占用时拒绝清理。
- 不引入独立的 HLS 分片缓存或 HTTP 代理服务。此处属于 mpv 自有临时缓存清理，不可用来宣称已实现跨播放器共享分片缓存。

## 验证边界与下一步

1. CI：运行单元测试、涉及文件的静态分析，并执行现有 Android Debug / Windows Release 构建流水线。构建不代表设备端可播或速度提升。
2. Android/Windows：实测同集同源 2.3.18 vs 2.3.19 首次出画、缓冲次数、总缓冲时间，记录测试网络和型号；未做对比不得宣称更快。
3. 人工断网、短暂恢复、持续404、解码报错、手动跳集/换源/退出；复核有限重试和同集识别，不误选集，弹幕开关与位置、倍速保留。
4. Android Wi-Fi/移动网络/后台状态、Windows 计量网络；核对预解析取消与网络权限。
5. 后续仅在 mpv 实际请求证明分片缓存命中及共享复用后，才设计并开启分片预取/淘汰；本次不进行不可证实的优化。
6. 正式 Android APK 必须使用 Google Drive 原 JKS，经用户可验证的私有签名环境构建；不得让公开 GitHub workflow 获得签名密钥。Windows 安装版需独立真实构建与升级验证。
