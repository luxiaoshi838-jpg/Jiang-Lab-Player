# 随播 2.3.15｜弹幕搜索与连接审计（2026-10-14）

## 用户实际故障
2.3.14 的番剧、国产电视剧、电影不是“自动未显示弹幕”，而是手动弹幕搜索也完全无法获得候选；必须首先恢复网络搜索和鉴权，之后才验证自动匹配及显示。

## 已定位的确定问题
1. 手动弹幕搜索页面原先仅调用 DanmakuApi.searchAnimes，而它使用 DanDanPlay X-AppId/X-Signature。没有正式 API 凭证、也没有已配置的兼容搜索服务时，请求不可能形成有效的已鉴权搜索。
2. Kazumi 上游源码同样使用 DANDANAPI_APPID/DANDANAPI_KEY；其发布工作流由 GitHub Actions secrets 注入。保留播放规则不等于拥有原发布者的 API 凭证。
3. 默认 api.danmu.icu 是 URL 弹幕接口，不提供兼容的作品名搜索、分集详情接口。不能作为手动检索服务冒充正常弹弹 Play。
4. GitHub Actions 运行 38510872612 的 danmaku-preflight 报告 `FAIL NO_DANMAKU_PROVIDER`，安卓与 Windows 候选构建被正确跳过；另一原有加密构建运行 38510872545 也因 `NO_DANMAKU_PROVIDER` 停止。

## 本分支已改
- DanmakuClient：保留上游签名；未提供服务时立即抛出明确错误，不发无效请求；对已配置且有效的兼容服务，搜索不泄露官方签名。
- DanmakuApi：支持官方原搜索优先和兼容后端的 `/api/v2/search/anime?keyword=` 备用搜索；不存在真实后端时仍失败，不伪造候选。
- 手动弹幕搜索：独立提示“服务未连接”，不再误判“未找到作品”；播放器对未连接和确实零结果分开提示。
- 版本：2.3.15+20315；保留 2.3.14 的 Kazumi 默认规则及 CMS 来源。
- 候选安装流程：正式搜索源需先实测《凡人修仙传》《亮剑》各自“搜索→作品→第一集→非空弹幕”，未通过则不构建 Android/Windows 安装包。
- 静态回归：增加“无凭证不得请求官方 API”和兼容搜索路由测试；CI 执行中时以 CI 最终结果为准。

## 签名和交付
Android 正式密钥已经在用户 Google Drive“签名文件”目录中定位：`随播_Android_正式签名密钥_20261010.zip`。本分支未下载、复制、改动或生成任何签名密钥；没有生成新的 APK 或安装版 EXE。最终必须使用原 JKS 本地签名，并核验包名 com.jianglab.suibo、versionCode=20315 与原正式证书 SHA256 一致。

## 当前阻塞
正式弹幕 API 凭证或可用的正式兼容服务不存在于当前 GitHub Actions secrets 环境。本分支修复了程序连接/错误处理，但尚不能证明 2.3.15 的弹幕获取功能已经恢复；不可交付“弹幕正常”的安装包。不能从 Android 签名密钥中推导 DanDanPlay API 密钥，也不能把第三方开发者私钥硬编码或公开到仓库。

## 二轮真实网络与跨服务修复（2026-10-14）
- 新增独立无凭证探测工作流（运行 38511628017，成功完成探测程序，不代表弹幕可用）。
- 官方弹弹 Play 未传应用鉴权的作品名搜索：HTTP 403；分集搜索：HTTP 403。
- 公开 api.danmu.icu 的官方示例链接请求：URLError，未取得有效弹幕。此服务亦不支持直接替代作品名搜索。
- 修复两种后端混用数字 episodeId：手动搜索对候选写入官方/兼容来源标志；进入分集详情、选择弹幕、记住用户确认关联、自动重新载入，都使用原来源；绝不把兼容库的数字 ID 请求到官方库。
- 规范兼容搜索返回格式：避免字符串 animeId、无效结果、显式 success=false 被误认为正常空结果；另加回归测试。
- 官方接口保留上游协议、开发者私密凭证要求。没有应用凭证或者已实际部署的兼容服务时，不可能保证可用的片名检索。签名 JKS 仅用于 Android APK 安装覆盖，与弹幕服务鉴权不同。
- 发布门禁继续拒绝生成无弹幕提供方的 APK/EXE。当前分支仅为待验收开发稿，不得宣称已在安卓/Windows 完成番剧/电影/电视剧实际弹幕验收。
