## 所有后续操作的最低日志规范

每轮必须记录以下内容，完成后检查文件已实际提交并能从 GitHub 查看：

| 字段 | 必填要求 |
| --- | --- |
| 日期/版本/操作序号 | 明确操作批次与时间，便于追溯 |
| 操作目标 | 用户的具体要求与本轮唯一处理对象 |
| 代码修改 | 文件路径、内容方向、关联提交 SHA |
| 配置修改 | 环境、**非敏感**键与实际值/默认值、前后差异 |
| 外部变更 | Render 服务名及脱敏配置、部署 ID、运行状态 |
| 测试和构建 | GitHub Actions 运行 ID、各步骤 PASS/FAIL/排队 |
| 签名与交付 | 使用的原密钥**文件名**、验签结果、产物版本/大小/报告，不提交密钥或二进制 |
| 未完成项 | 精确列出未完成、失败、受限、需要实体设备验收的事项 |

**安全底线：** 不得将 Android/Windows 签名私钥、JKS、keystore、密码、token、secret、完整签名媒体 URL、用户身份信息写入公开 GitHub。只能记录密钥项名称及是否配置，不得打印或储存具体值。不要为记录而触发无关扫描或额外重新构建。

**状态纪律：** 代码已提交、CI 已触发、CI 已通过、真实在线接口已通过、实体设备验收已通过、交付安装包存在，这些是不同状态，必须分别核验并写入。错误记录用追加更正纠正，不改写旧结论。
