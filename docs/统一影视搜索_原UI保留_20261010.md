# 随播：统一搜索与原书架兼容 — 2026-10-10

## 本轮用户确认范围
- **不能改变原来的基本功能与 UI 结构**，不增加影视分类页或独立入口。
- 原有搜索同时支持番剧、电视剧、电影、综艺、纪录片等。
- 原「追番」书架可以像收藏番剧一样收录非动画作品，复用原有播放器、选集、历史与续播。
- 软件名仍为「随播」，目标平台 Windows PC 与 Android。

## 代码调整
1. 删除上一版额外的「影视」导航入口和页面；导航恢复推荐、时间表、追番、我的四项。
2. 原 Bangumi 搜索支持动画 type=2 + 三次元 type=6；纯关键词另向用户已安装的视频规则搜索，合并展示在原结果卡片。
3. `BangumiItem` 新增 `sourcePlugin`/`sourceUrl`，使用已有 Hive typeId 0 的附加字段 15/16 持久化，旧记录缺字段时默认空值。
4. 规则来源作品使用 FNV 派生的高位正整数 ID（0x80000000..0xffffffff），既不与普通 Bangumi ID 重叠，也可充当 Hive 主键。
5. 在原书架本地保存收藏类型，源信息也随本地及 WebDAV 同步持久化，重开详情时优先显示原规则的原地址；重播继续使用原播放页。
6. 非动画和规则独立作品不上传 Bangumi **动画**收藏同步，避免云端拒绝、错误修改或影响原有番剧。
7. 规则未提供海报/评分时保留原卡片默认图片占位，不虚构元数据；高级 Bangumi 过滤仍针对元数据作品。
8. 源页面跳转与详情评论、评分网络接口做防护，防止规则作品被当作不存在的 Bangumi ID 加载而报错。
9. Github Actions 改为源码变更触发 Windows/Android 双端构建，并新增相关回归测试。

## 风险与限制
- 未安装规则时，只能发现 Bangumi 数据库索引的作品。
- 部分电影网站需要 Cookie、人机验证或持有访问授权；不能保证所有站点均能解析和播放。
- 规则搜索目前只返回名称与源 URL，**无封面的规则条目**使用默认占位，不添加虚假评分。
- 不能将首次 CI 通过等同于两端真实设备上的冷启动与完整播放验证。
- 正式 Android 签名密钥仍保存在 Google Drive 私有「签名文件」文件夹；GitHub 不包含密钥或密码。

## 2026-10-10：所有视频类型 + 原版弹幕功能（新增核验）
- 用户明确修正：**不是只增加电视剧和电影，而是所有视频类型**。规则搜索不对动画、电影、电视剧、综艺、纪录片、短剧、短视频、网络节目、课程、直播等做类型白名单限制。Bangumi type=2/6 只代表该元数据库的可检索视频范围，不是通用片种上限。
- 未分类的规则对象标记为本地 `type=0`，避免错误地将所有规则视频视作“真人三次元”；旧规则收藏凭 `isExternal` 仍然兼容，不依赖数值迁移。
- 用户要求**原版全部功能与 UI 以及弹幕都必须保留**：本轮未修改 `lib/pages/player/controller/player_danmaku_controller.dart`、`lib/pages/player/danmaku_source_sheet.dart`、`lib/request/apis/danmaku_api.dart`，仍使用原自动弹幕 Bangumi ID 映射、手动弹幕源切换、弹幕设置/屏蔽，播放继续走原 `VideoPageController` 和 `PlayerController`；原番剧真实 ID 不受规则对象影响。
- 补充直接视频单集/直播场景：对于明确的 HTTP(S) MP4/M4V/M3U8 直链，`SourceSheet` 生成单集 `Road`，`VideoPageController` 直接交给原播放器；其他网页 URL 仍使用原规则解析，避免误判与更改原播放行为。
- 弹幕边界：规则独立视频无真实 Bangumi ID，因此不能凭虚拟本地 ID保证自动匹配；有弹幕时仍可用原版手动检索/切换。原版番剧自动弹幕不丢失。
- 新增测试覆盖视频类别无白名单、直链与网页地址区分、原番剧 ID 和弹幕时间换算、既有收藏同步回归。
- 构建通过不等于已在 Android/Windows 真机验证，需要分别做冷启动、播放器、弹幕自动加载与手动选源回归。
